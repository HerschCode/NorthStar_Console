# `/v1` API — the data contract behind the Northstar console

Read-only JSON, public in demo mode. OpenAPI: `openapi/p1.json` (regenerated by `scripts/build_v1_snapshot.py`).
Every endpoint takes `as_of` (the replay clock) except the whole-log views; every business number is a *metric object*:

```json
{"value": 23.7, "unit": "%", "provenance": "measured", "source": "...", "as_of": "2018-04-16 00:00:00+00:00", "n": 3460, "note": "..."}
```

`provenance` is one of `measured`, `simulated` (rests on an assumption, which is echoed), `experimental` (weak model
signal), `pending` (data does not exist yet), `descriptive` (a fact about the case, not a model output).

## The replay clock
Every case in the BPI 2019 sample has finished, so "open cases" only exist relative to a clock. `src/replay/clock.py`:
open = started at or before `as_of` and not ended by it; its events are only those at or before `as_of`; risk is the
early-warning GRU ensemble on the first k ∈ {2, 3, 5} events, for the **realistic** target (training-window
per-category p75, ~100 days), never the configured SLA. A case already older than its target is `already_late`; one
with fewer than 2 events is `too_early`. A property test checks that truncating the log at `as_of` changes nothing.

Default clock **2018-04-16**: 3,089 open cases (2,517 scored, 544 already late), 3,670 cases whose target window has
elapsed. Earlier clocks have almost no decided cases; later ones are a long-tail backlog (the sample's cases nearly
all *start* in January 2018).

## Endpoints
| Endpoint | What it returns |
|---|---|
| `GET /v1/overview` | KPI strip (open, already late, at risk, value flagged, **simulated** expected loss, realistic-target breach rate with previous period, configured-SLA rate as a labelled secondary, AP exceptions, interventions = pending), risk funnel, open cases by business stage |
| `GET /v1/queue` | Open cases ranked by **expected loss** = P(breach) × order value × assumed breach-cost share (`config/expected_loss.yaml`, 2% placeholder); tiers are quantiles of expected loss, so a small order can never be CRITICAL; descriptive drivers (not attributions: the GRU has no SHAP) |
| `GET /v1/cases/{id}` | Case 360 up to the clock: timeline with idle gaps and business stage, risk + model quality for that k, expected loss, descriptive drivers, AP exceptions |
| `GET /v1/suppliers`, `/{id}` | Wilson-interval breach rates over cases whose target window has elapsed (still-open cases count as breached), ranked by CI lower bound, `min_n` default 20; cycle percentiles only from cases that have ended |
| `GET /v1/process/flow?group=stage\|activity` | Directly-follows graph; seven business stages from `config/stages.yaml` (a test fails on an unmapped activity); median/P75/P90 wait, breach-contribution share |
| `GET /v1/process/variants`, `/v1/risk-map` | Variants with share / breach rate; risk × value points and the 3×3 segment matrix |
| `GET /v1/finance/controls`, `/exceptions`, `/working-capital` | Control health (planted-anomaly recall; Benford **not valid**), exception summary, working capital (net-30 assumed) |
| `GET /v1/interventions/roi` | Logged (pending, 0) separated from simulated; model-vs-rules verdict |
| `GET /v1/models`, `/data-quality`, `/lineage`, `/experiments` | Model registry view (incl. early-warning AUC per k with CI), checks, lineage chains, every experiment including failed / leaked / tied ones |
| `GET /v1/briefing`, `/v1/search` | Structured facts with ids for the assistant to cite; search over cases, suppliers, experiments, controls |
| `PATCH /v1/interventions/{id}/outcome` | Record the post-intervention outcome (admin key, fail-closed) |

## Resilience
If the database is unreachable each endpoint serves `reports/v1_snapshot/<name>.json` (default clock only; any other
`as_of` returns 503) with `snapshot: {live: false, reason}`. `traceparent` is accepted and its trace id is logged and
echoed as `X-Trace-ID`.

## Honest limits
The early-warning model is a weak signal (see `/v1/models`); expected loss rests on an assumed cost share; interventions
are simulated until real outcomes are recorded; AP controls are anomaly triage; the sample's start-date concentration
limits what any clock can show.
